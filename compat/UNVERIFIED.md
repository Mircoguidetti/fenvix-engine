- **Pages that do not name the item.** 133 internal commands (`_configsvr*`, `_shardsvr*`, `donor*`, ...), 7 undocumented commands and 3 commands every driver sends but the 7.0 manual has no page for (`isMaster`, `saslStart`, `saslContinue`) have no command page; their `docs_url` is the command index or the page on the same mechanism, so the manual cannot confirm the *name*. Their existence is confirmed only by the real server's `listCommands`.
- **Docs v7.0 pages for later versions.** The v7.0 site also serves pages for `$rankFusion`, `$score`, `$scoreFusion`, `$querySettings`, `$listClusterCatalog`, `$toUUID`, `$serializeEJSON`, `$deserializeEJSON`, `$minMaxScaler`; mongod 7.0.45 rejects all of them ("Unrecognized pipeline stage" / "Unknown expression"), so they are not in the inventory. The query operator `$comment` is accepted by mongod 7.0.45 but has no 7.0 manual page, so it is not in the inventory either.
- **Atlas-only features** (`$search`, `$searchMeta`, `$vectorSearch`, Atlas Search index commands) cannot be differential-tested: mongod 7.0 itself rejects them. The engine's `$search` subset has no test against mongo:7.0.
- **Authentication beyond SCRAM, and TLS.** No mongod with TLS/x.509 material was provisioned, so X.509 and TLS are marked `missing` from the engine's source and a failed client connect, not from a differential test. Kerberos, LDAP, OIDC and AWS-IAM need Enterprise/Atlas infrastructure.
- **`txn:UnknownTransactionCommitResult`** is only produced after a failed commit; it cannot be induced without failpoints on either server.
- **Persistence and TTL tests** were run against an S3-compatible store (moto) because the MinIO image could not be pulled; the repository's own runbook uses MinIO. Behaviour against real MinIO/S3 was not re-verified. Replica-set behaviour was tested on single-node replica sets only (no secondaries, no election, no majority across nodes).
- **Drivers.** Only pymongo 4.19 and Node.js `mongodb` 7.7 were run. The inventory has no rows for the Java, Go, C#, Rust or other drivers; other language drivers that use the same server commands are expected to behave alike but that was not tested.
- **"Covered" is not "exhaustively correct".** It means at least one passing differential test exercises the row and none fails; it does not mean every argument combination was compared.
- **Client-only driver members** (properties, option holders, SDAM views, enum constants, event-emitter plumbing) are proposed as exclusions by rule (`compat/tools/driver_map.py`); each one was not individually checked for a hidden server dependency beyond that mapping.
- **Usage ranking.** The two usage scans are plain text matching over 10 repositories; see section 3 for known biases. Gaps the scans cannot measure are labelled *not measured*, and the order inside that block is by rows affected, not by usage.
- **Flaky or environment-sensitive results.** `cs.ttl_delete_event` fails in the pymongo harness (the delete event for a TTL expiry is not delivered) and passes in the Node.js harness; it is held against `cse:delete` as a failure. `update.extra.current_date` compares two wall-clock reads and cannot pass; it is treated as inconclusive, not as a failure or a pass. Probes whose two sides fail identically are reported as `invalid` and ignored as evidence.
