# MongoDB 7.0 driver-reachable surface: what FENVIX covers

Generated by `compat/tools/report.py` from `compat/inventory.csv` on 2026-10-27. Reference server: `mongo:7.0` = mongod 7.0.45 (`a52313e13a`). Engine: `mongo-server` built from `ff2ad26` (branch `compat-indexes`; engine source untouched by this audit). Docs: the MongoDB 7.0 manual (www.mongodb.com/docs/v7.0), pymongo 4.19 and mongodb (Node.js) 7.7 API references; every URL in the CSV was fetched (`compat/fetch_log.csv`).

## 1. Overall

**809 / 1245 covered = 65.0%** of the driver-reachable surface (rows proposed for exclusion are not counted).

Of the 1245 in-scope rows: 809 covered, 62 partial (supported with a stated difference), 35 untested (code exists, no differential test), 339 missing (engine rejects or ignores it). The inventory has 1793 rows; 548 are proposed exclusions (section 4).

`covered` means at least one passing differential test against mongo:7.0 and no failing one; the evidence column of the CSV names the tests. Two sources of tests were used: (a) the repository's own differential suite (`mongo-tests`: 3058 tests) run with pymongo (3055/3058 pass) and with the Node.js driver (3009/3009 pass); (b) 542 + 32 extra probes written for this audit (`compat/probes`, same method: identical request on real mongod and on the engine, canonical comparison): 272/542 (pymongo) and 24/32 (Node.js) identical.

Run notes: persistence tests and TTL tests were first run against a `--store local` engine and a stock mongod (TTL monitor sleeps 60 s) and failed for environmental reasons; they were re-run against an S3-compatible store (moto) and a mongod with `ttlMonitorSleepSecs=1`, and the re-run result replaces the first one (both stored in `compat/results/`). Replica-set tests ran against a single-node replica set. Failing after the re-runs: cs.ttl_delete_event, lookup.extra_let_pipeline_form, update.extra.current_date.

## 3b. Defects found while auditing (all reproducible with the probe named)

- createIndexes with several indexes creates only the first one while reporting success — probe `compat.opt.createIndexes.several_indexes_in_one_call`: fails on the engine
- replayed retryable writes execute twice — probe `compat.sessions.retryable_write_replay`: fails on the engine
- positional projection `arr.$` returns empty arrays — probe `compat.proj.positional`: fails on the engine
- documents come back in _id order instead of insertion order; $natural ignored — probe `compat.natural.sort`: fails on the engine
- a tailable cursor dies after the first batch — probe `compat.cursor.tailable_capped`: fails on the engine
- change stream `rename` event not emitted — probe `compat.cs.rename_and_drop_events`: ?
- fullDocument 'required' does not fail when no post-image exists — probe `compat.cs.fullDocument_required`: fails on the engine
- int64/double ordering near 2^53 and NaN under $lt differ — probe `compat.bson.compare_numeric`: fails on the engine
- `$where` has no `obj` variable — probe `compat.js.where_obj_alias`: fails on the engine
- operationTime/$clusterTime never returned to sessions — probe `compat.sessions.causal_consistency`: fails on the engine

## 5. Quality gate

- **Row counts vs the docs index pages:** `compat/verify_counts.md` — 48 independent recounts (different parsing code than the builder), 48 agree (1 with an explained difference), 0 unexplained differences.
- **Every row's URL:** `compat/verify_report.txt` — every `docs_url` returned HTTP 200 and the page contains the row's name (or the HTML anchor, for driver rows). Rows whose command exists only in `listCommands` point at the command index and are marked in `exclusion_reason`.
- **30 random rows against their docs page:** `compat/spot_check.md` (seeded, reproducible with `compat/tools/spot_check.py`); result and fixes are recorded there.
- **Evidence integrity:** `compat/tools/verify_evidence.py` re-checks that every test/probe cited in the CSV passed (or failed, for cited failures) in the stored results.

### What could not be verified

- **Pages that do not name the item.** 133 internal commands (`_configsvr*`, `_shardsvr*`, `donor*`, ...), 7 undocumented commands and 3 commands every driver sends but the 7.0 manual has no page for (`isMaster`, `saslStart`, `saslContinue`) have no command page; their `docs_url` is the command index or the page on the same mechanism, so the manual cannot confirm the *name*. Their existence is confirmed only by the real server's `listCommands`.
- **Docs v7.0 pages for later versions.** The v7.0 site also serves pages for `$rankFusion`, `$score`, `$scoreFusion`, `$querySettings`, `$listClusterCatalog`, `$toUUID`, `$serializeEJSON`, `$deserializeEJSON`, `$minMaxScaler`; mongod 7.0.45 rejects all of them ("Unrecognized pipeline stage" / "Unknown expression"), so they are not in the inventory. The query operator `$comment` is accepted by mongod 7.0.45 but has no 7.0 manual page, so it is not in the inventory either.
- **Atlas-only features** (`$search`, `$searchMeta`, `$vectorSearch`, Atlas Search index commands) cannot be differential-tested: mongod 7.0 itself rejects them. The engine's `$search` subset has no test against mongo:7.0.
- **Authentication beyond SCRAM, and TLS.** No mongod with TLS/x.509 material was provisioned, so X.509 and TLS are marked `missing` from the engine's source and a failed client connect, not from a differential test. Kerberos, LDAP, OIDC and AWS-IAM need Enterprise/Atlas infrastructure.
- **`txn:UnknownTransactionCommitResult`** is only produced after a failed commit; it cannot be induced without failpoints on either server.
- **Persistence and TTL tests** were run against an S3-compatible store (moto) because the MinIO image could not be pulled; the repository's own runbook uses MinIO. Behaviour against real MinIO/S3 was not re-verified. Replica-set behaviour was tested on single-node replica sets only (no secondaries, no election, no majority across nodes).
- **Drivers.** Only pymongo 4.19 and Node.js `mongodb` 7.7 were run. The inventory has no rows for the Java, Go, C#, Rust or other drivers; other language drivers that use the same server commands are expected to behave alike but that was not tested.
- **"Covered" is not "exhaustively correct".** It means at least one passing differential test exercises the row and none fails; it does not mean every argument combination was compared.
- **Client-only driver members** (properties, option holders, SDAM views, enum constants, event-emitter plumbing) are proposed as exclusions by rule (`compat/tools/driver_map.py`); each one was not individually checked for a hidden server dependency beyond that mapping.
- **Usage ranking.** The two usage scans are plain text matching over 10 repositories; see section 3 for known biases. Gaps the scans cannot measure are labelled *not measured*, and the order inside that block is by rows affected, not by usage.
- **Flaky or environment-sensitive results.** `cs.ttl_delete_event` fails in the pymongo harness (the delete event for a TTL expiry is not delivered) and passes in the Node.js harness; it is held against `cse:delete` as a failure. `update.extra.current_date` compares two wall-clock reads and cannot pass; it is treated as inconclusive, not as a failure or a pass. Probes whose two sides fail identically are reported as `invalid` and ignored as evidence.
