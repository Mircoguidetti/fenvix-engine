# results-gaps — closing the gaps found by the MongoDB 7.0 audit

Branch `compat-gaps` (from `compat-indexes`; no merge, no PR). Reference server for every comparison: **mongod 7.0.45** (official tarball, run unprivileged as a standalone on 27017 and as a single-node replica set `rs0` on 27020 with `ttlMonitorSleepSecs=1`; the suite uses its own copies on 28000+). Drivers: pymongo 4.19 and the Node.js driver (mongodb 7.7). "Identical" means: the same request sent to real mongod 7.0.45 and to the engine gives the same canonical result (values, BSON types, key order, error code, codeName and, where the test compares it, the message).

## Second round (founder's decisions A–E)

### B1/B3 — admin commands, implemented and tested with pymongo AND Node (`g11.admin.*`, `g10.params`, `g10.repl`, `g09.diag`)
`shutdown` (connection closed without reply, tenants closed; the db check comes before the field check, like mongod), `setParameter` (live effect for the JS limits, the transaction lifetime and FCV; others are stored and reported), `setDefaultRWConcern`, `fsync`/`fsyncUnlock` (a lock blocks writes — `maxTimeMS` expires with 50 — not reads), `logRotate`, `setClusterParameter`, `replSetGetStatus`, `replSetGetConfig`, `features`, `dropConnections`, `setFeatureCompatibilityVersion` (real transitions, run on throwaway server pairs), `rotateCertificates`, `setUserWriteBlockMode` (code 371, standalone and replica set), `invalidateUserCache` (unknown fields refused), `$queryStats` (admin-only stage with the full option validation incl. `hmacKey`; no statistics are collected, so it yields nothing, like a fresh mongod), `$toHashedIndexKey` (values equal to mongod's hash).

### B2 — search indexes
`createSearchIndexes`, `dropSearchIndex`, `updateSearchIndex`, `$listSearchIndexes`, and the driver members (`create_search_index(es)`, `drop/update/list_search_index`; Node equivalents), `$search`, `$searchMeta`. Mongod 7.0 Community answers all of them "only allowed on MongoDB Atlas", so the tests (`mongo-tests/search_index_test.py` 47, `search_test.py` + `search_ops_test.py` 143; Node mirrors) follow the Atlas documentation and the drivers' index-management spec: **not compared with a reference server**; limit: an index is `READY` and `queryable` at once (nothing is built in the background) and `$search` runs without needing an index definition.

### B4/B5 — driver members and encrypted fields
`g12` (10 py + 10 Node cases): `create_indexes`, `index_information`, `options`, the cursor option members, raw-batch and command cursors, change-stream cursors, session times, legacy GridFS (`GridFS.find/get_version/new_file`, `GridIn.abort/writelines`), `GridFSBucketReadStream.abort/end/start`, `Admin.removeUser`. `compactStructuredEncryptionData` is implemented (`g11.encryption.compact_rs/sa`, with `encryptedFields` collections created, refused on standalone like mongod).

### C — open gaps
Closed: `mapReduce` (all options; mongod's result order — also of `$group` — is random per process, proved by repeated runs, so compared sorted; the error texts, `inline` rules, `writeConcern`, `jsMode`, `verbose`, `bypassDocumentValidation` checks are identical), `validate` `full` (mongod prints transient storage-engine warnings for non-empty collections; reproduced), change-stream `modify` and `dropIndexes` expanded events, `create` `storageEngine`/`indexOptionDefaults` (name registry, `configString` type and key checks with WiredTiger's error text; empty documents are not stored; `collMod` refuses both), `$bucketAuto` granularity (all 13 series identical; the "other series rejected" note was obsolete), `$where` object alias, the numeric/tag `w` probes, `startAtOperationTime`, `$currentOp`/`$listSessions`/`$listLocalSessions`, session/causal-consistency probes (the earlier failures were the shared-session artifact, see "Probe harness").
Still open (15 rows, causes below): the 12 collation locales, `collation.backwards`, `collation.normalization`, BinData subtype 7.

### D — `cs.ttl_delete_event` (pymongo)
Not declared intermittent; investigated with load. **Valid runs, correct engine: 84 passes, 0 failures** — 40 before (10 Node + 30 pymongo with CPU busy loops), 40 now (30 pymongo + 10 Node with three busy loops and the 3989-test core suite running against the same machine), and 4 complete suite runs (two of them today) that include it. **Reproduced failure, 30 runs, 30 failures**: the "ours" engine of the test was an engine started **without `--ttl-sweep-secs 1`** (the load generator I used restarted the engine on 27018 with default flags: its TTL sweeper then runs every 60 s, the test waits 3 s, the `delete` event is missing: real `[insert, delete]`, ours `[insert]`). With the flag, the same test passes every time. This proves the mechanism of the symptom; it does **not** prove it was the cause of the single original failure (the suite starts its engines through `server.sh` with the flag in `SERVER_EXTRA`, and I found no place where it drops it). Reported as: symptom reproduced and explained under a misconfigured engine; original single failure not reproduced in 84 valid runs.

### E — MinIO
dl.min.io answers 410, so MinIO was **built from source** (Go 1.24.7; `.tools/gobin/minio`, listening on :9000 as an S3 store, bucket `bench`). On it: `gaps/g06_restart.py` (record of a retryable write survives an engine restart) PASS, and both full suite runs (4127 / 4127 in pymongo and in Node) — persistence, idle-close engines waking from the store, restart tests all run against real MinIO, not moto.

## Problems found and fixed in the final verification
- `shutdown` on a non-admin database must answer `Unauthorized` before the unknown-field check (found by `g10.repl.cmds_rs`, py and Node; fixed).
- `storageEngine`/`indexOptionDefaults` validation and storage, `collMod` refusing both, `invalidateUserCache` field check: found by the new differential tests; fixed.
- Harness: the pymongo gap harness now gives every case its own client. A raw `txnNumber` sent by one case on a pooled implicit session made a later retryable write of another case fail with `TransactionTooOld` on the engine only (it surfaced with the new g12 cases). The local-store engines of the gap runs now start with `--no-leases` (the local-file store cannot do the conditional `PutMode::Update` of lease renewal; `dropUser` of a missing user answered `InternalError` there; with the MinIO store the same command answers `UserNotFound`, checked). The Node `serverStatus` shape test no longer labels numbers int/float (a whole double and an int are the same JS number; the label depended on the live value of `locksPerKiloOp`).
- **Unexplained, mongod side**: once, a long-lived real mongod (27017, running since the machine restart, after many runs) rejected `zh@collation=stroke` ("Did you mean 'zh_Hant'?") while a fresh mongod, the same process after a restart, and `rs0` accept it. I could not reproduce it afterwards by running the complete pymongo and Node gap runs, the probes and the 3989-test core suite against fresh mongods. The engine follows the freshly started behaviour (valid). The real mongod was restarted for the final runs.

## Probe harness
`probe_refresh.py` / `node_probe.js` pair the standalone engine (27019) with the standalone mongod and the replica-set engine (27018) with `rs0`, with separate clients (the earlier single-client pairing poisoned later probes with `TransactionTooOld` on the engine side). Results: `compat/gaps_status/probe_*_final.json`.

## Open (not fixed), with the reason
- **12 collation locales** (`lv`, `se`, `se@collation=search`, `smn`, `smn@collation=search`, `kl`, `kl@collation=search`, `haw`, `en_US_POSIX`, and the `search` types of `cs`, `de`, `sk`): proved in `compat/gaps_status/icu_locale_proof.md` (`mongo-tests/gaps/gen_icu_proof.py`): the same strings sorted by mongod (ICU 57, CLDR 29), by the engine, and by the engine under `en`. For `se`, `smn`, `kl`, `haw`, `en_US_POSIX`, `de-search` the engine's order equals the root order (`icu_collator_data` 2.4.0, CLDR 49, has no tailoring for them); `lv`, `cs-search`, `sk-search` have a different CLDR-49 tailoring than CLDR 29. Closing them needs ICU 57's data (not available to the Rust ICU4X stack) or hand-written tailoring rules.
- **`collation.backwards`** for locales other than `fr_CA` and **`collation.normalization:false`** on non-FCD strings: the ICU4X collator has no runtime switch for either (refused with BadValue / always normalizes).
- **BinData subtype 7** (BSON column): mongod validates the payload and answers `NonConformantBSON` (378) for anything that is not a valid column; the engine stores any payload. Needs a BSON-column decoder.
- **Limits no test removes**: the search-index/`$search` family has no reference server (see B2); no multi-host SRV; the TLS options listed under item 3; `killOp` cannot stop a write half-applied; `$planCacheStats` is empty; profiler `planSummary` is approximate; JavaScript runs serialised on one thread and SpiderMonkey source positions in JS error messages are normalised, not reproduced; the change-stream history is kept in memory only (lost on restart); `explain` `parsedQuery` normalisation and view-explain details; file-system sizes in `dbStats` are 0; time-series `find` order is insertion order (mongod: bucket order); side effects of `setParameter` other than the live ones are not implemented; session records are in memory; `$queryStats` collects nothing.
